# T008 가상 resource_data 스키마 정의

- 단계: P1 (가상 스키마 정의 (회사 스키마와 구분))
- 상태: done (완료)
- 예상 소요: 20분
- 선행 작업: 없음
- 참고 problem.md: 3절

## 설명

resource id와 최소 속성을 가상으로 정의한다. 실제 연결 키는 미확인이므로 가상 스키마 내에서만 유효함을 명시한다.

## 완료 기준

- resource id가 eqp_step/lot_data와 일관되게 참조됨

## 쉬운 설명

resource_data는 T006(lot_data)과 T007(eqp_step)에서 참조되는 자원(resource) 데이터의 스키마를 정의하는 작업입니다.

구체적으로:
1. resource id 정의 — lot_data의 candidate_pairs와 eqp_step의 resource_id 필드에서 참조되는 자원의 식별자 체계를 명시합니다.
2. 최소 속성 정의 — 축소 로직이 resource를 선택·제외할 때 필요한 최소 정보(예: 자원명, 타입 등)를 정합니다.
3. 참조 일관성 — resource id가 lot_data와 eqp_step에서 동일하게 참조될 수 있도록 설계합니다.
4. 가상 스키마 명시 — 실제 회사 데이터의 연결 키와 필드는 미확인이므로, 이 스키마는 개발·검증용으로만 유효함을 명시합니다.

완료 기준은 'resource id가 eqp_step/lot_data에서 일관되게 참조될 수 있다'는 것입니다. 즉, 두 곳 모두에서 같은 형식의 resource id를 사용하고, 그 id가 실제로는 어떤 테이블의 키인지(미확인)를 문서에 명확히 표시해야 합니다.

## 피드백 로그

### 2026-09-16

완료기준 '일관되게 참조됨'을 문서가 L20-21에서 '이름(문자열) 일치로만 참조(완료 기준)'로 좁혀 자기충족적으로 재진술. 정작 참조 일관성이 실제로 깨지는 지점인 ID 일관 변경(problem.md 5절, T048/T049)을 전혀 다루지 않음 - resource_id가 변경 대상이고 lot_data.candidate_pairs[].resource / eqp_step.resource_id로 전파돼야 한다는 서술 없음(lot_data.md L20은 lot_id에 대해 명시함). 참조 수단이 문자열 동등성뿐인데 대소문자/공백 등 일치 기준 미정의(L20) - T054의 '존재하지 않는 resource 참조' 판정이 비결정적. resource_type/resource_name이 problem.md 5절 '공통 코드나 분류값을 임의로 ID로 취급하지 않는다'에 해당함을 표시 안 함(L31-33). 예시 resource_name 'Resource 01'이 resource_id 파생형이라 ID 변경 후 원본 id가 문자열에 남음(L43-45). 중복 id/없는 참조 deferral(L22-25, L58-61)이 T054를 인용하지 않아 lot_data.md 선례와 달리 추적 주체 없음. L62-64는 미존재 HANDOFF.md에 의무만 남기고 T005와 back-link 없음. 참조되지 않는 resource 행(T047 제외 대상)과 빈 resources[] 미언급. 반면 problem.md 3절 인용, 미확인 사항 재개방(L52-57), 형제 문서와의 상호참조 방향은 정확함 - 구조 추정 확정 위반은 없음.
