# T009 가상 위치·층 연결 스키마 정의

- 단계: P1 (가상 스키마 정의 (회사 스키마와 구분))
- 상태: done (완료)
- 예상 소요: 30분
- 선행 작업: 없음
- 참고 problem.md: 3절

## 설명

lot 현재 위치, 설비 층을 연결하는 별도 테이블을 가상으로 정의한다. 위치→층 산출 방식은 가상 규칙으로 명시한다.

## 완료 기준

- lot 위치 테이블과 설비 층 테이블이 분리되어 존재
- 위치 누락을 표현할 수 있는 구조(예: 결측 행)

## 쉬운 설명

지금까지 정의한 가상 스키마는 lot(생산 단위)과 설비·자원의 할당 관계만 다룹니다. T009에서는 위치와 층 정보를 추가로 정의합니다.

구체적으로:
- lot의 현재 위치 (예: 창고 A, 창고 B) — lot이 지금 어디에 있는지
- 설비가 위치한 층 (예: M01은 2층) — 각 설비가 건물의 어느 층에 있는지

이 두 정보를 별도 테이블로 정의하되, lot의 위치가 없거나 불명확한 경우도 표현할 수 있어야 합니다 (결측값 구조). 

완료 기준:
1. lot 위치 정보와 설비 층 정보가 분리된 테이블로 정의됨
2. 위치 누락(NULL 또는 결측 행)을 표현할 수 있는 구조 제시

주의: 실제 연결 테이블의 키 구조, 위치에서 층을 구하는 규칙은 아직 미확정(problem.md 3절 '위치와 층')이므로, 이 문서는 가상 스키마로서의 한계를 명시해야 합니다.

## 피드백 로그

### 2026-09-16

location_floor.md 리뷰: (1) 자기모순 - 44~48행은 '위치 누락 3형태 모두 7절 이미 결정된 정책(중단)'이라 하고 78~79행은 3번 형태(lookup 조회 실패) 처리 정책을 '정하지 않는다'고 함. (2) 오분류 - 57~64행이 eqp_floor에 행이 없는 경우를 '존재하지 않는 설비 참조'(미정, T054)로 보냄. eqp_floor는 설비 마스터가 아니므로 이건 층 정보 누락(7절 결정 정책, T053)이다. lot_location의 '행 없음'은 누락으로, eqp_floor의 '행 없음'은 참조 오류로 취급하는 비대칭에 근거가 없음. (3) 73~75행 가상 규칙이 location_id에 건물(A/B동)을 인코딩했는데 eqp_floor에는 건물이 없어, 5절 '현재 층/다른 층' 3유형이 건물 간 같은 층 번호에서 잘못 계산됨. (4) location_id 문자열의 층 숫자와 lookup.floor가 중복 보유되나 불일치 시 우선순위 미정 + location_id가 T048 대상이 되면 인코딩된 층이 깨지는 위험 미언급(T008 resource_name 지적과 동일 유형). (5) eqp_floor.floor=null인 설비가 후보에 있는 lot의 3유형 분류/분모 처리 미기술(T029 영향). (6) T054/T047은 인용하면서 정작 해당 정책 구현 작업인 T053, 소비자인 T029 미참조. (7) 19~21행이 resource_data의 exact match 규칙을 lot_id/eqp_id로 일방 확장 - lot_data.md/eqp_step_run_spec.md에는 그 규칙이 없음. (8) observed_at은 소비자 없고 null 불가 타입인데 LOT_V0003 예시는 location_id=null이면서 관측시각은 존재해 의미 모순. 완료 기준 2개는 문언상 충족, 문구 왜곡(자기충족화)은 없음.

### 2026-09-16

리뷰 반영: 위치 못 찾음 세 형태 + eqp_floor 행 부재를 모두 '이미 정해진 정책(T053)'으로 일관되게 재분류(기존에 3번 형태와 eqp_floor 행 부재를 T054로 잘못 보낸 자기모순 수정), T054(아직 미정)는 lookup 중복·설비 마스터 부재 시의 존재 자체 참조만으로 좁힘, location_id를 층 정보를 인코딩하지 않는 완전 불투명 문자열로 재설계(건물 가정·파생값 중복 문제를 구조적으로 제거), observed_at 필드 삭제(소비처 없고 null 모순 사례가 있었음), 예시에 '단일 층/현재 층에서만' 등 problem.md 5절의 나머지 유형 추가, T029/T053 참조 추가, resource_data.md 참조 규칙을 이 문서가 '채택'하는 것으로 정정(원 문서들이 선언한 것처럼 오인용했던 것 수정).
